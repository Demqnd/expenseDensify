# Document 1 – Project Charter
# Modified June 12
# expenseDensify
# Purpose
- The purpose of this project is to build a complete software system while gaining practical experience with modern software engineering and development practices.
- This project is not intended to become a production-ready expense management platform.
- The primary objective is to experience the complete Software Development Life Cycle (SDLC) and understand how modern applications move from initial concept through deployment and operation.
- The final application should be functional but does not need to be feature-rich.
- Learning and understanding are more important than the finished product.
---
# Project Vision
- expenseDensify aims to simulate a real-world software project while remaining small enough to complete independently.
- The application should demonstrate the complete process of planning, designing, developing, testing, deploying, and maintaining a modern software system.
- The goal is to gain practical experience and build confidence discussing technical decisions.
---
# Problem Statement
- Expense tracking frequently requires users to manually enter information from receipts.
- Manual entry introduces repetitive work and increases the likelihood of mistakes.
- expenseDensify will simplify this process by allowing users to upload receipts and automatically extract information using OCR and AI before user review.
- The project also provides a structured environment for learning full-stack development and software architecture.

# Success Criteria
The project will be considered successful if:
- Users can authenticate
- Users can upload receipts
- OCR extracts receipt information
- Users can review and edit extracted values
- Expense information is stored successfully
- The application runs locally
- Docker supports deployment
- CI/CD executes successfully
- AWS deployment succeeds
- Technical decisions can be explained confidently

---
# Project Scope
The application will allow users to:
- Log in
- Upload receipts
- Extract receipt information using OCR and AI
- Create expenses
- Edit expenses
- View expense history
- Manage users (administrator)
The application will not include:
- Payroll processing
- Accounting integrations
- Multi-company support
- Mobile applications
- Advanced approval workflows
- Complex reporting
The objective is learning, not feature completeness.
---
# Constraints
The project will operate under the following constraints:
- Limited development time
- Educational project scope
- Preference toward low-cost technologies
- Learning prioritized over optimization
---
# Risks
Potential risks include:
- Project scope becoming too large
- AI and OCR increasing complexity
- Cloud deployment challenges
- Attempting too many technologies simultaneously
Mitigation strategy:
- Prioritize MVP functionality
- Build incrementally
- Keep architecture simple
- Deploy locally before cloud deployment
